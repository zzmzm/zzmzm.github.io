CLI 参考

tiyi CLI 是驱动 UI 的同一个 ConnectRPC API 的瘦客户端。本页按资源整理当前运维命令；示例只列常用 flag。写入前请运行 tiyi <command> --help，并以已安装二进制为准。

鉴权模式

CLI 用两种方式之一与太一通信。本地命令不需要 token；远程命令需要 API URL 与一个 JWT。

模式flag鉴权使用场景
本地管理 socket (默认) Unix socket 上的 OS 文件权限 跑在与 tiyi run 同一主机上。
远程 --api URL --token JWT Authorization: Bearer header 中的 HS256 JWT 从工作站或 CI runner 操作。

从用户名/密码取一个 JWT：

$ tiyi auth login --api http://controller:8080 --username admin
# 输入密码,打印 JWT,可选写入 ~/.config/tiyi/credentials

诊断

在安装前后都可以在目标主机上运行 tiyi doctor,它默认不会修改系统,只高亮提示配置加载错误、systemd 可用性、sudo PATH 问题、已安装服务的状态目录所有权问题,以及 API / 仪表盘与代理端口的监听占用。如果还没有安装 systemd unit,状态目录所有权检查会跳过,除非传入 --service-user/--service-group 或显式请求修复。状态目录修复必须显式执行且需要 root:sudo tiyi doctor --fix-state-ownership。

$ tiyi doctor
$ tiyi doctor --mode agent
$ tiyi doctor --proxy-http-addr :8180 --proxy-https-addr :18443
$ sudo tiyi doctor --fix-state-ownership

声明式 apply

kubectl 风格入口。一份 YAML、一条命令、一行审计。apply 创建不存在的资源、更新发生漂移的资源；完全相同的重复 apply 报 unchanged 且不写库。apply 永不删除 - manifest 里缺失的资源不会被移除。

$ tiyi apply -f site.yaml          # 计划 + 落库
$ tiyi apply -f site.yaml --dry-run  # 逐资源显示 create/update/unchanged，不写库
$ tiyi apply -f - < site.yaml       # 从 stdin 读取 manifest
$ tiyi get site                       # 以 JSON 查看当前状态（upstream | site | policy | cert | iplist）
$ tiyi get upstream <id>              # 按 ID 查看单个资源

交叉引用（upstreamRef、certRef、policyRef）在任何写入之前按名字解析；引用不存在则整体报 unresolved_reference 失败。proxy apply failed 是另一类错误：资源已落库但数据面拒绝了配置包（例如上游健康检查预探失败）- 修好后用同一份 manifest 重新 apply 即可收敛。

apiVersion: tiyi.io/v1
kind: Upstream
metadata:
  name: app-pool
spec:
  backends:
    - url: http://10.0.0.11:8080   # weight 默认 100；权重为相对值
    - url: http://10.0.0.12:8080
  loadBalance: round_robin         # 目前唯一支持的策略
  healthCheck: { path: /healthz, intervalSeconds: 10 }
---
apiVersion: tiyi.io/v1
kind: Site
metadata:
  name: example-com
spec:
  primaryHost: example.com
  aliases: [www.example.com]
  upstreamRef: app-pool            # 按名字引用；或 upstreamsInline: [{url: ...}]（二选一）
  tls: { mode: none }              # none | uploaded | managed_acme（另有 certRef、minVersion、httpBehavior）
  waf: { enabled: true, mode: blocking }  # policyRef 可选；缺省用内置 Standard
  status: active                   # active | disabled
---
apiVersion: tiyi.io/v1
kind: IpList
metadata:
  name: office-allowlist
spec:
  kind: ALLOW                      # ALLOW | DENY | MONITOR
  entries:
    - { cidr: 203.0.113.0/24, description: office, expireAt: 2026-12-31T00:00:00Z }
    - { cidr: geo:CN }

支持的 kind：Upstream（backends[]、loadBalance、healthCheck、status）、Site（primaryHost、aliases[]、upstreamRef/upstreamsInline[]、tls、waf、status）、Policy（engineState、blockingMode、crsRulesetRef、status）、IpList（kind、entries[] 支持 cidr/geo:CC）。证书请用 tiyi cert upload/cert issue 管理，再在 Site 里按名字引用。资源按 (kind, name) 匹配；spec 严格校验，未知字段直接报错而不是被忽略。一个文件里的多个文档按顺序 apply，后面的文档可以按名字引用前面的文档。

退出码

码含义
0成功。
1通用错误。输出说明。
2使用方法 / flag 解析错误。
3需要鉴权或 token 被拒绝。
4资源未找到。
5前置条件失败（例如版本冲突、UPSTREAM_IN_USE）。
